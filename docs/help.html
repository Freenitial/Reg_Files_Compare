1OverviewPrésentation

REG Files Compare loads two or more .reg files, takes one as the reference, and shows each file in its own column: a tree of keys above, the values of the selected key below. Everything that differs from the reference is colored, and a key or a value selected in one column is selected in every column that shows it.

Policies and settings

Compare the policies or settings exported from several machines, users or images, and see which ones drifted.

Before and after

Export a key before and after an installation, an update or a change of setting, and see exactly what was written.

Extract

Copy keys and values as text, or export a key, a branch or a few values to a new .reg file.

Files only

The application compares the files you give it: its code never reads or writes the registry of your machine. To compare a live registry, export it first, with Registry Editor (File › Export) or reg export.

REG Files Compare charge deux fichiers .reg ou plus, en prend un comme référence et affiche chaque fichier dans sa colonne : l'arbre des clés en haut, les valeurs de la clé choisie en bas. Tout ce qui diffère de la référence est coloré, et une clé ou une valeur choisie dans une colonne est sélectionnée dans chaque colonne qui l'affiche.

Stratégies et réglages

Comparez les stratégies ou réglages exportés de plusieurs machines, utilisateurs ou images, et voyez lesquels ont dérivé.

Avant et après

Exportez une clé avant et après une installation, une mise à jour ou un changement de réglage, et voyez exactement ce qui a été écrit.

Extraire

Copiez des clés et des valeurs en texte, ou exportez une clé, une branche ou quelques valeurs dans un nouveau fichier .reg.

Des fichiers, seulement

L'application compare les fichiers que vous lui donnez : son code ne lit ni n'écrit jamais le registre de votre machine. Pour comparer un registre en place, exportez-le d'abord, avec l'Éditeur du Registre (Fichier › Exporter) ou reg export.

2Getting startedPrise en main

  1. Download Reg_Files_Compare.exe from the latest release and run it. Nothing to install, no .NET runtime needed. The file is signed by Leo Antonin Gillet.
  2. Load the files: Browse .reg Files, or drop files and folders on the window. You can also drop them on the exe's icon, or give them on the command line: a new window opens with them, and compares them at once when there are two or more.
  3. Pick the Reference (the first file loaded, by default).
  4. Press Compare.
  5. Follow the colors: select a key to see its values, select a value to see it in every file.

F1 or the Help button opens this page.

  4. Appuyez sur Compare.

4Reading a comparisonLire une comparaison

Every column is compared with the reference column, marked (REF). The colors and the weight mean:

LookKeyValue
GreenExists in this file, not in the reference.Same.
RedExists in the reference, not in this file (struck through).Same color, not struck through; name only: this file has no type or data for it.
BlueExists in both, but one of its own values is added, missing or different.Exists in both with different data.
BoldSomething changed there. In a compared column: the key is added or missing, or one of its own values is added, missing or different (a key whose subkeys alone changed stays normal); a value is bold when it is added, missing or different. In the reference column: a key is bold when the key itself, one of its values or one of its subkeys at any depth differs in at least one other file; a value, when it differs in at least one other file. Path levels above the keys of the files (HKEY_LOCAL_MACHINE, for instance) are never bold.
NormalIdentical to the reference.

A column shows the keys of its own file and of the reference: a key that only another file has does not appear in it. The reference column shows its own keys only. After each comparison, the branches that lead to a change are opened and the others closed; the selected key and value stay selected in the columns that show them.

Filters

BoxEffect (not on the reference column)
Show only changes (on)The tree keeps only the keys that changed and the branches leading to them; the values grid hides the identical values.
Hide empty added nodes (off)Hides the added keys that have no subkey left in the tree (values are not taken into account), level after level, and the path levels left empty above them.

Both apply at once, without comparing again. The trees are rebuilt: the selected key and value stay selected wherever they are still shown, and the branches return to their automatic open or closed state, except the parents of the selected key, which are opened.

When the comparison is made again

  • Compare builds it from the ticked files (two at least); with fewer, it removes the file columns.
  • From then on (as soon as a comparison of two files or more starts), the display follows the file list: ticking or unticking a file, choosing another reference, adding files (they arrive ticked) or removing one compares again by itself. Unticking down to a single file removes the file columns; ticking a second one brings the comparison back. This lasts until the list is emptied.
  • Before the first comparison, nothing compares by itself (except the files given at start-up, see Getting started).
  • Choosing an unticked file as reference ticks it. An unticked reference is replaced by the first ticked file at the next comparison; a removed one, by the first file of the list.
  • A change made while a comparison runs is applied when it ends: the columns always match the last state of the list. A removed file's column goes at once; the others stay until the new ones replace them. The search columns stay where they are.

While a comparison runs, the file list fills with a progress bar.

Chaque colonne est comparée à la colonne de référence, marquée (REF). Les couleurs et la graisse signifient :

AspectCléValeur
VertExiste dans ce fichier, pas dans la référence.Pareil.
RougeExiste dans la référence, pas dans ce fichier (barrée).Même couleur, sans être barrée ; nom seul : ce fichier n'a ni type ni donnée pour elle.
BleuExiste des deux côtés, mais l'une de ses propres valeurs est ajoutée, manquante ou différente.Existe des deux côtés avec une donnée différente.
GrasQuelque chose a changé là. Dans une colonne comparée : la clé est ajoutée ou manquante, ou l'une de ses propres valeurs est ajoutée, manquante ou différente (une clé dont seules les sous-clés ont changé reste normale) ; une valeur est en gras quand elle est ajoutée, manquante ou différente. Dans la colonne de référence : une clé est en gras quand elle-même, l'une de ses valeurs ou l'une de ses sous-clés, à toute profondeur, diffère dans au moins un autre fichier ; une valeur, quand elle diffère dans au moins un autre fichier. Les niveaux de chemin au-dessus des clés des fichiers (HKEY_LOCAL_MACHINE, par exemple) ne sont jamais en gras.
NormalIdentique à la référence.

Une colonne montre les clés de son fichier et celles de la référence : une clé que seul un autre fichier possède n'y apparaît pas. La colonne de référence ne montre que ses propres clés. Après chaque comparaison, les branches qui mènent à un changement sont ouvertes et les autres fermées ; la clé et la valeur choisies restent sélectionnées dans les colonnes qui les affichent.

Filtres

CaseEffet (pas sur la colonne de référence)
Show only changes (cochée)L'arbre ne garde que les clés qui ont changé et les branches qui y mènent ; la grille des valeurs cache les valeurs identiques.
Hide empty added nodes (décochée)Cache les clés ajoutées qui n'ont plus de sous-clé dans l'arbre (les valeurs ne comptent pas), niveau après niveau, et les niveaux de chemin restés vides au-dessus d'elles.

Les deux s'appliquent tout de suite, sans nouvelle comparaison. Les arbres sont reconstruits : la clé et la valeur choisies restent sélectionnées partout où elles sont encore affichées, et les branches reviennent à leur ouverture automatique, sauf les parents de la clé choisie, qui sont ouverts.

Quand la comparaison est refaite

  • Compare la construit à partir des fichiers cochés (deux au moins) ; avec moins, il retire les colonnes de fichiers.
  • Dès lors (dès qu'une comparaison de deux fichiers ou plus commence), l'affichage suit la liste des fichiers : cocher ou décocher un fichier, choisir une autre référence, ajouter des fichiers (ils arrivent cochés) ou en enlever un relance la comparaison d'elle-même. Décocher jusqu'à ne laisser qu'un fichier retire les colonnes de fichiers ; en recocher un deuxième ramène la comparaison. Cela dure jusqu'à ce que la liste soit vidée.
  • Avant la première comparaison, rien ne se compare de soi-même (sauf les fichiers donnés au démarrage, voir Prise en main).
  • Choisir comme référence un fichier décoché le coche. Une référence décochée est remplacée par le premier fichier coché à la comparaison suivante ; une référence enlevée, par le premier fichier de la liste.
  • Un changement fait pendant le calcul d'une comparaison est appliqué à la fin de celui-ci : les colonnes correspondent toujours au dernier état de la liste. La colonne d'un fichier enlevé disparaît aussitôt ; les autres restent jusqu'à ce que les nouvelles les remplacent. Les colonnes de recherche restent à leur place.

Pendant le calcul, la liste des fichiers se remplit d'une barre de progression.

5NavigatingNaviguer

  • Synchronized selection. Select a key in any column: every file column selects the same key (opening its parents) if its tree shows it, and clears its selection otherwise; no value stays selected. Select a value in any column, search columns included: the value of the same name is selected in every column that lists it (a search column follows only while it shows that key; a value picked in a search column takes the columns to its key first). A column that follows does not scroll the columns area sideways.
  • Expand All / Collapse All open or close every branch of every file column.
  • Sizes. Drag a column's right edge to resize it (200 px at least), the bar between tree and values to share the height. The Name and Type columns of the values grids are shared by all columns: drag their separator, or double-click it to fit the names or types listed in that column's grid.
  • Several values. In a values grid, a click selects or unselects a row: several rows can be selected for the copy and export commands, which take them in the order they were clicked. Right-click one of the selected rows: a right-click on another row selects it alone. The other columns follow the first selected row.
  • Counters. Under each tree: the keys and values of the file, and the values of the selected key.
  • Dark Theme switches between dark (at start) and light, title bar included.
  • Sélection synchronisée. Choisissez une clé dans n'importe quelle colonne : chaque colonne de fichier sélectionne la même clé (en ouvrant ses parents) si son arbre la montre, et vide sa sélection sinon ; aucune valeur ne reste choisie. Choisissez une valeur dans n'importe quelle colonne, colonnes de recherche comprises : la valeur de même nom est sélectionnée dans chaque colonne qui l'affiche (une colonne de recherche ne suit que tant qu'elle montre cette clé ; une valeur choisie dans une colonne de recherche emmène d'abord les colonnes à sa clé). Une colonne qui suit ne fait pas défiler la zone des colonnes sur le côté.
  • Expand All / Collapse All ouvrent ou ferment toutes les branches de toutes les colonnes de fichiers.
  • Tailles. Faites glisser le bord droit d'une colonne pour la redimensionner (200 px au moins), la barre entre l'arbre et les valeurs pour partager la hauteur. Les colonnes Name et Type des grilles de valeurs sont communes à toutes les colonnes : faites glisser leur séparateur, ou double-cliquez dessus pour l'ajuster aux noms ou aux types listés dans la grille de cette colonne.
  • Plusieurs valeurs. Dans une grille de valeurs, un clic sélectionne ou désélectionne une ligne : plusieurs lignes peuvent être choisies pour les commandes de copie et d'export, qui les prennent dans l'ordre des clics. Faites un clic droit sur l'une des lignes choisies : un clic droit sur une autre ligne la sélectionne seule. Les autres colonnes suivent la première ligne choisie.
  • Compteurs. Sous chaque arbre : les clés et valeurs du fichier, et les valeurs de la clé choisie.
  • Dark Theme bascule entre le sombre (au démarrage) et le clair, barre de titre comprise.

6SearchRecherche

Type some text in the search box and press Enter: a Search: … column is added at the right. It lists, file by file, the keys whose path, or the name or data of one of whose values, contains the text (ignoring case). Names and data are searched as the grids show them: a DWORD by its hexadecimal or decimal value (0x0000000a (10)), a multi-string by its text, the default value as (Default). What the grid does not show is not searched (dword:, the bytes of an EXPAND_SZ or MULTI_SZ), but a BINARY value, which the grid shows as written, is found by that text (hex:01,02). The text is taken without its leading and trailing spaces.

  • The search covers the ticked files (all loaded files if none is ticked), as they are at that moment: the column does not update afterwards.
  • Select a result: the file columns jump to that key, and the column's own grid shows the values that matched (all the values of the key when only its path matched). The first result is selected at once. Each file group shows the file name (its tooltip, the full path), and each result the full key path; (no results) says that nothing matched. The search tree has no right-click menu.
  • Several searches can stay open; X closes one. They stay at the right when the comparison is made again.

Tapez un texte dans la zone de recherche et appuyez sur Entrée : une colonne Search: … s'ajoute à droite. Elle liste, fichier par fichier, les clés dont le chemin, ou le nom ou la donnée de l'une de leurs valeurs, contient le texte (sans tenir compte de la casse). Noms et données sont cherchés tels que les grilles les affichent : un DWORD par sa valeur hexadécimale ou décimale (0x0000000a (10)), une chaîne multiple par son texte, la valeur par défaut sous le nom (Default). Ce que la grille n'affiche pas n'est pas cherché (dword:, les octets d'une valeur EXPAND_SZ ou MULTI_SZ), mais une valeur BINARY, que la grille affiche telle qu'écrite, se trouve par ce texte (hex:01,02). Le texte est pris sans ses espaces de début et de fin.

  • La recherche porte sur les fichiers cochés (tous les fichiers chargés si aucun ne l'est), tels qu'ils sont à cet instant : la colonne ne se met pas à jour ensuite.
  • Choisissez un résultat : les colonnes de fichiers sautent à cette clé, et la grille de la colonne montre les valeurs trouvées (toutes les valeurs de la clé quand seul son chemin correspondait). Le premier résultat est choisi d'emblée. Chaque groupe de fichier montre le nom du fichier (son info-bulle, le chemin complet), et chaque résultat le chemin complet de la clé ; (no results) dit que rien ne correspond. L'arbre de recherche n'a pas de menu contextuel.
  • Plusieurs recherches peuvent rester ouvertes ; X en ferme une. Elles restent à droite quand la comparaison est refaite.

7Copy and exportCopier et exporter

Right-click the tree of a file column, or a values grid (a search column's grid has the three Copy commands, not Export):

CommandResult
Copy Row (tree)The name of the selected key: its last segment, not its full path.
Copy Row + Children (tree)The key and the subkeys this column shows, drawn as a text tree (├─, └─). Grayed out when the key shows no subkey.
Export... (tree)A .reg file with the key, all its subkeys and all their values, taken from this column's file (whatever the filters show). When the file has no key there, the status bar says so and nothing is written.
Copy Row(s) (values)One line per selected value: name, type and data separated by tabs, ready to paste into a spreadsheet. A field holding a line break, a tab or a double quote (a MULTI_SZ value, a string on several lines) is put in double quotes, its own quotes doubled, so it stays in one cell.
Copy Name / Copy Data (values)The names, or the data as displayed. One value: copied as it is. Several: one value per line, quoted the same way when needed.
Export... (values, file columns)A .reg file with the selected values of the selected key. Only the rows the grid lists can be selected: with Show only changes on, identical values cannot be exported this way. A red value (missing from this file) is not written; when none of the selected values is in the file, the status bar says so and nothing is written.

An export keeps the format of the file it comes from: Registry Editor version 5 (UTF-16 with BOM), or REGEDIT4 (ANSI) for a REGEDIT4 file. Key and value names are written as that file writes them, and data exactly as read (a value split over several lines is written on one line). The parent keys are listed as empty headers, so the file keeps the path without importing anything else; a deletion entry ([-HKEY_…]) is written alone, without parents. The status bar says where the file was written, or why it could not be (a character the ANSI code page of a REGEDIT4 file cannot write is refused, never replaced by a look-alike).

Clic droit sur l'arbre d'une colonne de fichier, ou sur une grille de valeurs (celle d'une colonne de recherche a les trois commandes Copy, pas Export) :

CommandeRésultat
Copy Row (arbre)Le nom de la clé choisie : son dernier segment, pas son chemin complet.
Copy Row + Children (arbre)La clé et les sous-clés que cette colonne affiche, dessinées en arbre texte (├─, └─). Grisée quand la clé n'affiche aucune sous-clé.
Export... (arbre)Un fichier .reg avec la clé, toutes ses sous-clés et toutes leurs valeurs, prises dans le fichier de cette colonne (quoi que montrent les filtres). Quand le fichier n'a aucune clé à cet endroit, la barre d'état le dit et rien n'est écrit.
Copy Row(s) (valeurs)Une ligne par valeur choisie : nom, type et donnée séparés par des tabulations, lignes prêtes à coller dans un tableur. Un champ qui contient un saut de ligne, une tabulation ou un guillemet double (une valeur MULTI_SZ, une chaîne sur plusieurs lignes) est mis entre guillemets doubles, les siens doublés, pour rester dans une seule cellule.
Copy Name / Copy Data (valeurs)Les noms, ou les données telles qu'affichées. Une valeur : copiée telle quelle. Plusieurs : une valeur par ligne, chacune mise entre guillemets de la même façon si besoin.
Export... (valeurs, colonnes de fichiers)Un fichier .reg avec les valeurs choisies de la clé choisie. Seules les lignes que la grille affiche peuvent être choisies : avec Show only changes cochée, les valeurs identiques ne peuvent pas être exportées ainsi. Une valeur rouge (absente de ce fichier) n'est pas écrite ; quand aucune des valeurs choisies n'est dans le fichier, la barre d'état le dit et rien n'est écrit.

Un export garde le format du fichier dont il vient : Éditeur du Registre version 5 (UTF-16 avec BOM), ou REGEDIT4 (ANSI) pour un fichier REGEDIT4. Les noms de clés et de valeurs sont écrits comme ce fichier les écrit, et les données exactement telles que lues (une valeur coupée sur plusieurs lignes est écrite sur une seule). Les clés parentes sont listées en en-têtes vides : le fichier garde le chemin sans rien importer d'autre ; une entrée de suppression ([-HKEY_…]) est écrite seule, sans parents. La barre d'état dit où le fichier a été écrit, ou pourquoi il n'a pas pu l'être (un caractère que la page de codes ANSI d'un fichier REGEDIT4 ne sait pas écrire est refusé, jamais remplacé par un caractère ressemblant).

8Good to knowBon à savoir

  • Names ignore case, data does not. Software and SOFTWARE are the same key; "On" and "ON" are different data. A key or value name is shown with the letter case of the first compared file that has it, the reference first, so a difference of case alone is never shown as a change. A path level that is not a key of its own (SOFTWARE in most exports) takes the case of the first key below it, which can differ from one column to another; a search column shows each file's own spelling.
  • Names as in Registry Editor. The default value (@) reads (Default), and names are shown without their .reg escapes (C:\\Windows reads C:\Windows). A value literally named "(Default)" is a different value from the default one.
  • Data is compared as written. The same number written two ways (dword:0000000a and hex(4):0a,00,00,00) counts as different. Exports in the same format compare cleanly: Registry Editor (version 5, its default) and reg export write the same way. Long values split over several lines (\ at the end) are joined first, so the line length does not matter.
  • Strings on several lines. Registry Editor writes the line breaks of a string as they are: the value continues on the following lines up to its closing quote. The grid shows it on several lines.
  • Deletion entries ([-HKEY_…], "Value"=-) are compared as written, like any other key or value.
  • Files are read once, when they are loaded. To see a file changed on disk, remove it and load it again.
  • Encodings. Version 5 files (UTF-16, with or without BOM) and UTF-8 files are read as they are. A REGEDIT4 file without a byte order mark is ANSI: it is read in the code page of your system (Windows-1252 on a Western European system), and so are its EXPAND_SZ and MULTI_SZ data. A REGEDIT4 export and a version 5 export of the same key still differ on every EXPAND_SZ and MULTI_SZ value (their bytes are ANSI in one, UTF-16 in the other): compare exports made in the same format.
  • Folders dropped on the window or the exe, or given on the command line, are searched for .reg files, 32 levels deep at most; hidden and system files and folders, and the subfolders that cannot be read, are skipped, and a folder that cannot be read at all is reported. A file without extension given directly is taken when its text starts with a .reg header (Windows Registry Editor… or REGEDIT4). A path that does not exist is skipped without a message (unless nothing at all is found).
  • Any file can be opened with Browse .reg Files (its All files filter). A file without any key is loaded all the same, and the status bar says so.
  • Large keys. The values grids create only the rows on screen, so a key with thousands of values opens at once.
  • Les noms ignorent la casse, les données non. Software et SOFTWARE sont la même clé ; "On" et "ON" sont des données différentes. Un nom de clé ou de valeur s'affiche avec la casse du premier fichier comparé qui le contient, la référence d'abord : une simple différence de casse n'est donc jamais signalée comme un changement. Un niveau de chemin qui n'est pas une clé à part entière (SOFTWARE dans la plupart des exports) prend la casse de la première clé en dessous, qui peut varier d'une colonne à l'autre ; une colonne de recherche montre l'orthographe de chaque fichier.
  • Les noms comme dans l'Éditeur du Registre. La valeur par défaut (@) s'affiche (Default), et les noms s'affichent sans leurs échappements .reg (C:\\Windows se lit C:\Windows). Une valeur nommée littéralement "(Default)" est une autre valeur que la valeur par défaut.
  • Les données sont comparées telles qu'écrites. Un même nombre écrit de deux façons (dword:0000000a et hex(4):0a,00,00,00) compte comme différent. Des exports au même format se comparent sans surprise : l'Éditeur du Registre (version 5, son format par défaut) et reg export écrivent de la même manière. Les longues valeurs coupées sur plusieurs lignes (\ en fin de ligne) sont d'abord recollées : la longueur des lignes ne compte donc pas.
  • Chaînes sur plusieurs lignes. L'Éditeur du Registre écrit les sauts de ligne d'une chaîne tels quels : la valeur continue sur les lignes suivantes jusqu'à son guillemet fermant. La grille l'affiche sur plusieurs lignes.
  • Les entrées de suppression ([-HKEY_…], "Valeur"=-) sont comparées telles qu'écrites, comme toute autre clé ou valeur.
  • Les fichiers sont lus une fois, au chargement. Pour voir un fichier modifié sur le disque, enlevez-le puis rechargez-le.
  • Encodages. Les fichiers version 5 (UTF-16, avec ou sans BOM) et UTF-8 sont lus tels quels. Un fichier REGEDIT4 sans BOM est en ANSI : il est lu dans la page de codes de votre système (Windows-1252 sur un système d'Europe occidentale), ses données EXPAND_SZ et MULTI_SZ aussi. Un export REGEDIT4 et un export version 5 de la même clé diffèrent tout de même sur chaque valeur EXPAND_SZ et MULTI_SZ (leurs octets sont ANSI dans l'un, UTF-16 dans l'autre) : comparez des exports faits au même format.
  • Les dossiers déposés sur la fenêtre ou sur l'exe, ou passés en ligne de commande, sont fouillés à la recherche de fichiers .reg, sur 32 niveaux au plus ; les fichiers et dossiers cachés ou système, et les sous-dossiers illisibles, sont ignorés, et un dossier entièrement illisible est signalé. Un fichier sans extension donné directement est pris quand son texte commence par un en-tête .reg (Windows Registry Editor… ou REGEDIT4). Un chemin qui n'existe pas est ignoré sans message (sauf si rien n'est trouvé).
  • Tout fichier peut être ouvert avec Browse .reg Files (son filtre All files). Un fichier sans aucune clé est tout de même chargé, et la barre d'état le dit.
  • Grosses clés. Les grilles de valeurs ne créent que les lignes visibles : une clé de plusieurs milliers de valeurs s'ouvre tout de suite.

Flow

App registers the parser, the drop resolver, the theme service and the main view-model as singletons, shows the window and loads the files given on the command line. Columns are created by MainWindowViewModel for each comparison. The heavy part, building the DiffEngine, runs on the thread pool (Task.Run); the columns are then built on the UI thread one after the other, with a yield to the dispatcher at Background priority between two columns so the progress bar is painted. The reference that Compare settles on is written under a guard (_settingReference), so only a user's choice compares again.

10Reading .reg filesLecture des fichiers .reg

Services/RegFileParser.cs reads the whole file into memory and turns it into a RegFile: path, name, last write time, size, IsRegedit4, and Data, a dictionary key path → value name → raw value text. Both levels ignore case (OrdinalIgnoreCase).

Encoding

  1. A byte order mark decides: FF FE UTF-16 LE, FE FF UTF-16 BE, EF BB BF UTF-8.
  2. No mark, but a zero byte in the first 512 bytes: UTF-16 LE.
  3. A file starting with REGEDIT4: the system's ANSI code page (GetACP, through CodePagesEncodingProvider).
  4. Otherwise strict UTF-8; if the bytes are not valid UTF-8, the ANSI code page.

Lines

  • Each line is stripped of its leading and trailing blanks. Empty lines and lines starting with ; are skipped.
  • The first line that is not empty is the header: REGEDIT4 sets IsRegedit4. Lines before the first key are not values.
  • […] opens a key: the text between the brackets is its path. A key that appears twice is one key.
  • A value line: a quoted name, whose closing quote is found by honoring \" and \\ (the name is kept as written, escapes included), then =; or an unquoted name before the first =, where @, the default value, is stored under the empty name, as in the registry. The raw value is the rest of the line, stripped of its blanks.
  • A raw value that opens a quote without closing it on its line is a string holding line breaks: it goes on, line after line, until the closing quote, the lines joined with CR LF and kept as they are (the first line keeps its trailing blanks; the rest of the last line, after the quote, is dropped).
  • A raw value that does not start with a quote and ends with \ continues on the next lines, each stripped of its blanks and appended without the \, until a line that does not end with one. Those lines are taken as they come: an empty line ends the value, a comment line inside it is read as data.
  • A value that appears twice in a key keeps its last data.

Services/RegFileParser.cs lit tout le fichier en mémoire et en fait un RegFile : chemin, nom, date de dernière modification, taille, IsRegedit4, et Data, un dictionnaire chemin de clé → nom de valeur → texte brut de la valeur. Les deux niveaux ignorent la casse (OrdinalIgnoreCase).

Encodage

  1. Une marque d'ordre des octets décide : FF FE UTF-16 LE, FE FF UTF-16 BE, EF BB BF UTF-8.
  2. Pas de marque, mais un octet nul dans les 512 premiers octets : UTF-16 LE.
  3. Un fichier qui commence par REGEDIT4 : la page de codes ANSI du système (GetACP, par CodePagesEncodingProvider).
  4. Sinon UTF-8 strict ; si les octets ne sont pas de l'UTF-8 valide, la page de codes ANSI.

Lignes

  • Chaque ligne est débarrassée de ses blancs de début et de fin. Les lignes vides et celles qui commencent par ; sont ignorées.
  • La première ligne non vide est l'en-tête : REGEDIT4 fixe IsRegedit4. Les lignes avant la première clé ne sont pas des valeurs.
  • […] ouvre une clé : le texte entre crochets est son chemin. Une clé qui apparaît deux fois est une seule clé.
  • Une ligne de valeur : un nom entre guillemets, dont le guillemet fermant est trouvé en respectant \" et \\ (le nom est gardé tel qu'écrit, échappements compris), puis = ; ou un nom sans guillemets avant le premier =, où @, la valeur par défaut, est rangée sous le nom vide, comme dans le registre. La valeur brute est le reste de la ligne, débarrassé de ses blancs.
  • Une valeur brute qui ouvre un guillemet sans le fermer sur sa ligne est une chaîne qui contient des sauts de ligne : elle continue, ligne après ligne, jusqu'au guillemet fermant, les lignes jointes par CR LF et gardées telles quelles (la première garde ses blancs de fin ; la fin de la dernière ligne, après le guillemet, est ignorée).
  • Une valeur brute qui ne commence pas par un guillemet et se termine par \ continue sur les lignes suivantes, chacune débarrassée de ses blancs et ajoutée sans le \, jusqu'à une ligne qui ne se termine pas par \. Ces lignes sont prises telles qu'elles viennent : une ligne vide termine la valeur, une ligne de commentaire en son milieu est lue comme une donnée.
  • Une valeur qui apparaît deux fois dans une clé garde sa dernière donnée.

11The comparison engineLe moteur de comparaison

Services/DiffEngine.cs is built once per comparison, from the ticked files with the reference at index 0, and is not modified afterwards.

  • AllKeys: key path → the files that have it. AllValues: key path → value name → the files that have it. Both keep the spelling of the first file that has the name, the reference first. SortedKeys: every key path in tree order (KeyPathComparer: level by level, each level's names without regard to case, so A\X comes before AB).
  • Key status in a file: the reference gives Reference (or Hidden if it lacks the key); another file Added (only it), Missing (only the reference), Exists (both) or Hidden (neither).
  • Value status: Added, Missing or Hidden on the same rule; when both have it, Identical if the raw texts are equal (StringComparison.Ordinal), else Different.
  • A key changed in a file when it is Added or Missing there, or when one of the value names any compared file has under it is Added, Missing or Different there.
  • For each file, the set of changed keys and all their ancestors is computed once (KeyOrSubtreeChanged, then a constant-time lookup), and their union over the other files for the reference (ChangedAnywhereForKey). ValueChangedAnywhere tells, for the reference, whether a value differs in at least one other file.

Cost: one pass over every key and value of every file to build the indexes, then, per non-reference file, one status per key, and at most one per value name of the union.

Services/DiffEngine.cs est construit une fois par comparaison, à partir des fichiers cochés avec la référence à l'index 0, et n'est plus modifié ensuite.

  • AllKeys : chemin de clé → les fichiers qui l'ont. AllValues : chemin de clé → nom de valeur → les fichiers qui l'ont. Les deux gardent l'orthographe du premier fichier qui a le nom, la référence d'abord. SortedKeys : tous les chemins de clés dans l'ordre de l'arbre (KeyPathComparer : niveau par niveau, les noms de chaque niveau sans tenir compte de la casse, donc A\X avant AB).
  • État d'une clé dans un fichier : la référence donne Reference (ou Hidden si elle n'a pas la clé) ; un autre fichier Added (lui seul), Missing (la référence seule), Exists (les deux) ou Hidden (aucun).
  • État d'une valeur : Added, Missing ou Hidden selon la même règle ; quand les deux l'ont, Identical si les textes bruts sont égaux (StringComparison.Ordinal), sinon Different.
  • Une clé a changé dans un fichier quand elle y est Added ou Missing, ou quand l'un des noms de valeurs qu'un fichier comparé a sous elle y est Added, Missing ou Different.
  • Pour chaque fichier, l'ensemble des clés changées et de tous leurs ancêtres est calculé une fois (KeyOrSubtreeChanged, ensuite consulté en temps constant), ainsi que leur union sur les autres fichiers pour la référence (ChangedAnywhereForKey). ValueChangedAnywhere dit, pour la référence, si une valeur diffère dans au moins un autre fichier.

Coût : un passage sur chaque clé et valeur de chaque fichier pour construire les index, puis, par fichier autre que la référence, un état par clé, et au plus un par nom de valeur de l'union.

12Building the columnsConstruction des colonnes

Tree (FileColumnViewModel.BuildTree)

  1. For each key of SortedKeys: skipped if its status here is Hidden, or if Show only changes is on, the column is not the reference, and neither the key nor anything under it changed.
  2. The path is split on \; a node is created for each segment not yet in the tree (a dictionary indexes the nodes by path).
  3. The node of the key itself gets its status. Added or Missing → bold. If one of its values is Added, Missing or Different → bold, and blue when the key itself exists on both sides. In the reference column, bold when ChangedAnywhereForKey. The nodes of path levels that are not keys get no status.
  4. Hide empty added nodes (not on the reference): depth first, an Added node, or a path level, without children is removed, from the tree and from the index (so a key chosen elsewhere is not selected here either); its parent is examined after it, hence the cascade.
  5. Each node is expanded when one of its descendants is a change, collapsed otherwise.

Values grid

  • The rows are the value names that any compared file has under the selected key, sorted with OrdinalIgnoreCase (the default value first). If this file lacks the key, the grid stays empty (the struck-through node already says so).
  • Other columns, Show only changes on: Added, Missing and Different only. Off: everything but Hidden. Reference: the values it has.
  • Type and data come from this file's raw value, empty for a Missing value. Bold: changed here; in the reference, changed in some other file (ValueChangedAnywhere).
  • The grid is a ListBox on a VirtualizingStackPanel: only the rows on screen are created. The Data column takes the width of the widest datum (DataColumnWidth): each datum is first estimated from its characters' advances (each character measured once, then cached), and only the 16 widest estimates are measured exactly (FormattedText in the theme's font, Inter, bold, 12 px).

Selection

The selected key path and value name (empty for the default value, null for none) live in MainWindowViewModel. A column that changes them notifies the others, which apply them with their own notifications suppressed (no loop); a new key clears the value. A filter change rebuilds the trees and grids under the same suppression, then applies the shared key and value again; a theme change rebuilds no tree (their bindings are only refreshed, so open branches and the selected key stay as they are), it re-creates the grid rows of the selected key, then applies the shared value again. A comparison applies the shared key and value to every new column. Each column stops the requests to bring a row into view (RequestBringIntoView) that its own tree and grid leave unhandled, so the columns area never scrolls to follow another column. Key paths and value names are matched without case.

Arbre (FileColumnViewModel.BuildTree)

  1. Pour chaque clé de SortedKeys : sautée si son état ici est Hidden, ou si Show only changes est cochée, que la colonne n'est pas la référence et que ni la clé ni rien en dessous n'a changé.
  2. Le chemin est découpé sur \ ; un nœud est créé pour chaque segment pas encore dans l'arbre (un dictionnaire indexe les nœuds par chemin).
  3. Le nœud de la clé elle-même reçoit son état. Added ou Missing → gras. Si l'une de ses valeurs est Added, Missing ou Different → gras, et bleu quand la clé existe des deux côtés. Dans la colonne de référence, gras quand ChangedAnywhereForKey. Les nœuds des niveaux de chemin qui ne sont pas des clés ne reçoivent aucun état.
  4. Hide empty added nodes (pas sur la référence) : en profondeur d'abord, un nœud Added, ou un niveau de chemin, sans enfant est retiré, de l'arbre et de l'index (une clé choisie ailleurs n'y est donc pas sélectionnée non plus) ; son parent est examiné après lui, d'où la cascade.
  5. Chaque nœud est ouvert quand l'un de ses descendants est un changement, fermé sinon.

Grille des valeurs

  • Les lignes sont les noms de valeurs qu'un fichier comparé a sous la clé choisie, triés avec OrdinalIgnoreCase (la valeur par défaut d'abord). Si ce fichier n'a pas la clé, la grille reste vide (le nœud barré le dit déjà).
  • Autres colonnes, Show only changes cochée : Added, Missing et Different seulement. Décochée : tout sauf Hidden. Référence : les valeurs qu'elle a.
  • Type et donnée viennent de la valeur brute de ce fichier, vides pour une valeur Missing. Gras : changée ici ; dans la référence, changée dans un autre fichier (ValueChangedAnywhere).
  • La grille est une ListBox sur un VirtualizingStackPanel : seules les lignes visibles sont créées. 14Search, export, loadingRecherche, export, chargement

Search (SearchColumnViewModel)

Built once from the term and the list of files it covers. For each file and each key: the key matches if its path contains the term; a value matches if its name as shown, or the text GetDisplayValue gives for it, contains the term (OrdinalIgnoreCase). Results are grouped per file, keys in tree order. Selecting a key sets the shared selection, so the file columns follow; its grid lists the matched values, or every value when only the key matched, and takes part in the value selection like a file column's.

Export (RegFileWriter)

  • Header Windows Registry Editor Version 5.00, or REGEDIT4 for a REGEDIT4 file, and an empty line; then one […] header for each parent of the exported key, from the hive down, without values (none for a deletion entry).
  • Key and value names take the file's own spelling: the columns show the spelling of the first file that has a name.
  • Tree export: the key and every key of the file whose path starts with key\, in tree order, each with all its values sorted by name, then an empty line. Values export: the key and the selected values found in the file.
  • Values are written "name"=raw (@=raw for the default value), the raw text exactly as read. Lines end with CR LF. The file is written in UTF-16 LE with a BOM, as Registry Editor does, or for a REGEDIT4 file in the ANSI code page without any mark, a character it cannot write being refused (EncoderFallback.ExceptionFallback). A tree export of a path level that is not a key writes no header for it, nor for the levels down to the first keys below it.
  • The proposed name is the last segment of the key, with characters that are not allowed in file names replaced by _. A write that fails (no write access, a full disk) is told in the status bar.

Loading (DragDropService, MainWindowViewModel)

  • A dropped or passed folder: its first entry is read (a folder that cannot be listed is reported), then Directory.EnumerateFiles(folder, "*.reg") with RecurseSubdirectories, MaxRecursionDepth = 32 (a junction pointing to a parent would loop) and IgnoreInaccessible (hidden and system entries are skipped, as by default). A file ending in .reg: taken. A file with another extension: ignored. A file without extension: taken if its first 4 KB, decoded as the parser would, start with a .reg header. A path that does not exist: skipped. A path that cannot be read is reported in the status bar, and the others are still loaded.
  • Each path is made absolute; a file already loaded (same path, ignoring case) is not loaded again. A file without any key is loaded. Each of these cases, and a file that cannot be read, is told in the status bar, and the comparison that follows keeps those messages beside its count; a file that fails to load is also written to the console output (which only shows when the output is redirected).
  • Display names: the file name when every loaded file is in the same folder, the full path otherwise. The columns show the file name, with the full path as a tooltip.

Title bar

When the window opens, and on every theme change: DwmSetWindowAttribute with DWMWA_USE_IMMERSIVE_DARK_MODE (attribute 20, and 19 for Windows 10 builds before 20H1; the one Windows does not know is ignored), then SetWindowPos(SWP_FRAMECHANGED), a WM_NCACTIVATE off/on pair and RedrawWindow(RDW_FRAME), so the frame is repainted at once rather than at the next activation.

Recherche (SearchColumnViewModel)

Construite une fois à partir du terme et de la liste des fichiers couverts. Pour chaque fichier et chaque clé : la clé correspond si son chemin contient le terme ; une valeur correspond si son nom tel qu'affiché, ou le texte que GetDisplayValue donne pour elle, contient le terme (OrdinalIgnoreCase). Les résultats sont groupés par fichier, clés dans l'ordre de l'arbre. Choisir une clé règle la sélection commune, que les colonnes de fichiers suivent ; sa grille liste les valeurs trouvées, ou toutes les valeurs quand seule la clé correspondait, et prend part à la sélection de valeur comme celle d'une colonne de fichier.

Export (RegFileWriter)

  • En-tête Windows Registry Editor Version 5.00, ou REGEDIT4 pour un fichier REGEDIT4, et une ligne vide ; puis un en-tête […] pour chaque parent de la clé exportée, depuis la ruche, sans valeurs (aucun pour une entrée de suppression).
  • Les noms de clés et de valeurs prennent l'orthographe du fichier lui-même : les colonnes montrent celle du premier fichier qui a le nom.
  • Export d'arbre : la clé et chaque clé du fichier dont le chemin commence par clé\, dans l'ordre de l'arbre, chacune avec toutes ses valeurs triées par nom, puis une ligne vide. Export de valeurs : la clé et les valeurs choisies trouvées dans le fichier.
  • Les valeurs s'écrivent "nom"=brut (@=brut pour la valeur par défaut), le texte brut exactement tel que lu. Les lignes finissent par CR LF. Le fichier est écrit en UTF-16 LE avec BOM, comme le fait l'Éditeur du Registre, ou pour un fichier REGEDIT4 dans la page de codes ANSI sans aucune marque, un caractère qu'elle ne sait pas écrire étant refusé (EncoderFallback.ExceptionFallback). L'export d'arbre d'un niveau de chemin qui n'est pas une clé n'écrit d'en-tête ni pour lui, ni pour les niveaux qui le séparent des premières clés en dessous.
  • Le nom proposé est le dernier segment de la clé, les caractères interdits dans un nom de fichier remplacés par _. Une écriture qui échoue (pas le droit d'écrire, disque plein) est signalée dans la barre d'état.

Chargement (DragDropService, MainWindowViewModel)

  • Un dossier déposé ou passé : sa première entrée est lue (un dossier impossible à lister est signalé), puis Directory.EnumerateFiles(dossier, "*.reg") avec RecurseSubdirectories, MaxRecursionDepth = 32 (une jonction vers un dossier parent bouclerait) et IgnoreInaccessible (les entrées cachées et système sont ignorées, comme par défaut). Un fichier en .reg : pris. Un fichier d'une autre extension : ignoré. Un fichier sans extension : pris si ses 4 premiers Ko, décodés comme le ferait l'analyseur, commencent par un en-tête .reg. Un chemin qui n'existe pas : ignoré. Un chemin illisible est signalé dans la barre d'état, et les autres sont tout de même chargés.
  • Chaque chemin est rendu absolu ; un fichier déjà chargé (même chemin, sans tenir compte de la casse) n'est pas rechargé. Un fichier sans aucune clé est chargé. Chacun de ces cas, et un fichier illisible, est signalé dans la barre d'état, et la comparaison qui suit garde ces messages à côté de son décompte ; un fichier dont le chargement échoue est aussi écrit dans la sortie console (visible seulement quand la sortie est redirigée).
  • Noms affichés : le nom du fichier quand tous les fichiers chargés sont dans le même dossier, le chemin complet sinon. Les colonnes montrent le nom du fichier, avec le chemin complet en info-bulle.

Barre de titre

À l'ouverture de la fenêtre et à chaque changement de thème : DwmSetWindowAttribute avec DWMWA_USE_IMMERSIVE_DARK_MODE (attribut 20, et 19 pour les versions de Windows 10 antérieures à 20H1 ; celui que Windows ne connaît pas est ignoré), puis SetWindowPos(SWP_FRAMECHANGED), une paire WM_NCACTIVATE désactivé/activé et RedrawWindow(RDW_FRAME), pour que le cadre soit redessiné tout de suite et non à la prochaine activation.

15Security and privacySécurité et confidentialité

  • No registry access in its code. The application contains no registry call; it reads .reg files only. Like any Windows program, the process still reads system settings through Windows and the .NET runtime (the time zone used for file dates, for instance), and the standard Open and Save dialogs remember the last folders in the user's registry.
  • No connection of its own. No telemetry, no update check, no download. This page is local; its links open GitHub only when you click them, and it remembers its language and theme in your browser's local storage.
  • No elevation. The manifest requests no administrator rights: the application runs with yours.
  • What it reads: the files you open, drop or pass on the command line (wholly, into memory), the folders you drop or pass on the command line, to find .reg files in them, and the first 4 KB of a file without extension, to check its header.
  • What it writes: the .reg files you export, where you choose, and this page, written again each time it is opened, to %TEMP%\Reg_Files_Compare\REG Files Compare - Help.html, then opened by Windows with your browser. No settings, no log file.
  • Signature. Released executables are signed with Authenticode (SHA-256) by the certificate Leo Antonin Gillet, issued by HARICA, and timestamped (RFC 3161), so the signature stays valid after the certificate expires. Check it in the file's Properties › Digital Signatures, or with Get-AuthenticodeSignature .\Reg_Files_Compare.exe.
  • Manifest: per-monitor DPI awareness (v2); long-path aware (effective when long paths are enabled in Windows).
  • Aucun accès au registre dans son code. L'application ne contient aucun appel au registre ; elle ne lit que des fichiers .reg. Comme tout programme Windows, le processus lit tout de même des réglages système par Windows et le runtime .NET (le fuseau horaire des dates de fichiers, par exemple), et les boîtes de dialogue standard Ouvrir et Enregistrer retiennent les derniers dossiers dans le registre de l'utilisateur.
  • Aucune connexion de son fait. Ni télémétrie, ni recherche de mise à jour, ni téléchargement. Cette page est locale ; ses liens n'ouvrent GitHub que si vous cliquez dessus, et elle retient sa langue et son thème dans le stockage local de votre navigateur.
  • Aucune élévation. Le manifeste ne demande aucun droit d'administrateur : l'application s'exécute avec les vôtres.
  • Ce qu'elle lit : les fichiers que vous ouvrez, déposez ou passez en ligne de commande (en entier, en mémoire), les dossiers que vous déposez ou passez en ligne de commande, pour y trouver les fichiers .reg, et les 4 premiers Ko d'un fichier sans extension, pour vérifier son en-tête.
  • Ce qu'elle écrit : les fichiers .reg que vous exportez, là où vous le choisissez, et cette page, réécrite à chaque ouverture dans %TEMP%\Reg_Files_Compare\REG Files Compare - Help.html, puis ouverte par Windows avec votre navigateur. Ni réglages, ni fichier journal.
  • Signature. Les exécutables publiés sont signés Authenticode (SHA-256) par le certificat Leo Antonin Gillet, délivré par HARICA, et horodatés (RFC 3161) : la signature reste valide après l'expiration du certificat. Vérifiez-la dans Propriétés › Signatures numériques du fichier, ou avec Get-AuthenticodeSignature .\Reg_Files_Compare.exe.
  • Manifeste : DPI par écran (v2) ; compatible avec les chemins longs (effectif quand Windows les autorise).

16Build, signing and testsCompilation, signature et tests

Requirements: Windows 10 1809 or later (x64), the .NET 11 SDK, and for the release build Visual Studio (or its Build Tools) with the Desktop development with C++ workload, whose linker Native AOT uses. Details in BUILD.md.

dotnet build      # Debug build
dotnet test       # unit tests
.\build.cmd       # tests, Native AOT publish, checks, then build\Reg_Files_Compare.exe
.\sign.cmd        # Authenticode signature + timestamp (hardware token)
  • build.cmd first deletes any previous build\Reg_Files_Compare.exe, stops at the first failure, and puts the new exe in build\ only once every step passed. It checks that no library (.dll) was left beside the published exe and that the exe holds its compiled XAML: the .NET 11 SDK publishes Native AOT “optimized” by default, which skips Avalonia's XAML compiler, so Directory.Build.props sets UseOptimizedPublish=false.
  • sign.cmd chooses the certificate before signing (current user store, private key present, valid today, code-signing usage, subject common name exactly Leo Antonin Gillet; SIGN_THUMBPRINT picks one if several match), signs with signtool /sha1, timestamps separately (no key needed, so up to four attempts without asking for the PIN again), verifies the signature and its timestamp, and checks that the file carries the chosen certificate.
  • Tests (xUnit): the parser (keys and values, comments, quoted names with = and escaped quotes, the default value, strings on several lines, hex continuation lines, UTF-16 without BOM, REGEDIT4 and ANSI files, headers of files without extension), the comparison engine (key and value statuses, tree order, KeyOrSubtreeChanged, ChangedAnywhereForKey, ValueChangedAnywhere), the type formatter (ANSI and odd byte counts included), the export (parents, deletion entries, default value, the file's own spelling, REGEDIT4 and its encoding, read back), the drop resolver (depth, files without extension, an unreadable subfolder or folder), the copied text, the help page, and the main window driven without a screen (Avalonia.Headless with Skia and the Inter font): when the comparison is made again, replays, selection kept by comparisons, filters and theme, search columns (their place, their value selection), hidden nodes, load messages, and the Data column's width against the text as drawn.
