1OverviewPrésentation

REG Files Compare loads two or more .reg files, takes one as the reference, and shows each file in its own column: a tree of keys above, the values of the selected key below. Everything that differs from the reference is colored, and a key or a value selected in one column is selected in every column that shows it.

Policies and settings

Compare the policies or settings exported from several machines, users or images, and see which ones drifted.

Before and after

Export a key before and after an installation, an update or a change of setting, and see exactly what was written.

Extract

Copy key names, a branch as a text tree, or values as text; export a branch (a key with all its subkeys) or chosen values to a new .reg file.

Files only

The application compares the files you give it: its code never reads or writes the registry of your machine. To compare a live registry, export it first, with Registry Editor (File › Export) or reg export.

REG Files Compare charge deux fichiers .reg ou plus, en prend un comme référence et affiche chaque fichier dans sa colonne : l'arbre des clés en haut, les valeurs de la clé choisie en bas. Tout ce qui diffère de la référence est coloré, et une clé ou une valeur choisie dans une colonne est sélectionnée dans chaque colonne qui l'affiche.

Stratégies et réglages

Comparez les stratégies ou réglages exportés de plusieurs machines, utilisateurs ou images, et voyez lesquels ont dérivé.

Avant et après

Exportez une clé avant et après une installation, une mise à jour ou un changement de réglage, et voyez exactement ce qui a été écrit.

Extraire

Copiez en texte des noms de clés, une branche sous forme d'arbre ou des valeurs ; exportez une branche (une clé et toutes ses sous-clés) ou des valeurs choisies dans un nouveau fichier .reg.

Des fichiers, seulement

L'application compare les fichiers que vous lui donnez : son code ne lit ni n'écrit jamais le registre de votre machine. Pour comparer un registre en place, exportez-le d'abord, avec l'Éditeur du Registre (Fichier › Exporter) ou reg export.

4Reading a comparisonLire une comparaison

Every column is compared with the reference column, marked (REF). The colors and the weight mean:

LookKeyValue
GreenExists in this file, not in the reference.Same.
RedExists in the reference, not in this file (struck through).Same color, not struck through; name only: this file has no type or data for it.
BlueExists in both, but one of its own values is added, missing or different.Exists in both with different data.
BoldSomething changed there. In a compared column: the key is added or missing, or one of its own values is added, missing or different (a key whose subkeys alone changed stays normal); a value is bold when it is added, missing or different. In the reference column: a key is bold when the key itself, one of its values or one of its subkeys at any depth differs in at least one other file; a value, when it differs in at least one other file. Path levels above the keys of the files (HKEY_LOCAL_MACHINE, for instance) are never bold.
NormalIdentical to the reference.

A column shows the keys of its own file and of the reference: a key that only another file has does not appear in it. The reference column shows its own keys only. After each comparison, the branches that lead to a change are opened and the others closed, except the parents of the selected key, which are opened; the selected key and value stay selected in the columns that show them.

Data is compared by what it holds, not by how the file writes it: dword:0000000A and dword:a, hex:0A,0B and hex:0a, 0b, a dword: and the same number as hex(4):, a REGEDIT4 hex(2) (ANSI bytes) and a version 5 one (UTF-16 bytes) holding the same text are all identical. Strings compare exactly, case included (a line break of the data counts as one, whether the file ends its lines with \r\n or \n). Try it below.

Filters

BoxEffect (not on the reference column)
Show only changes (on)The tree keeps only the keys that changed and the branches leading to them; the values grid hides the identical values.
Hide empty added nodes (off)Hides the added keys that have no subkey left in the tree (values are not taken into account), level after level, and the path levels left empty above them.

Both apply at once, without comparing again. The trees are rebuilt: the selected key and value stay selected wherever they are still shown, and the branches return to their automatic open or closed state, except the parents of the selected key, which are opened.

When the comparison is made again

  • Compare builds it from the ticked files (two at least); with fewer, it removes the file columns (or says to tick two when there are none). The selected key and value are kept for the next comparison.
  • From then on (as soon as a comparison of two files or more starts), the display follows the file list: ticking or unticking a file, choosing another reference, adding files (they arrive ticked) or removing one compares again by itself. Unticking down to a single file removes the file columns; ticking a second one brings the comparison back, with the same key and value selected. This lasts until the list is emptied.
  • Before the first comparison, nothing compares by itself (except the files given at start-up, see Getting started).
  • Choosing an unticked file as reference ticks it. An unticked reference is replaced by the first ticked file at the next comparison; a removed one, by the first file of the list.
  • A change made while a comparison runs is applied when it ends: the columns always match the last state of the list. A removed file's column goes at once; the others stay until the new ones replace them. The search columns stay where they are.

While a comparison runs, the file list fills with a progress bar.

Chaque colonne est comparée à la colonne de référence, marquée (REF). Les couleurs et la graisse signifient :

AspectCléValeur
VertExiste dans ce fichier, pas dans la référence.Pareil.
RougeExiste dans la référence, pas dans ce fichier (barrée).Même couleur, sans être barrée ; nom seul : ce fichier n'a ni type ni donnée pour elle.
BleuExiste des deux côtés, mais l'une de ses propres valeurs est ajoutée, manquante ou différente.Existe des deux côtés avec une donnée différente.
GrasQuelque chose a changé là. Dans une colonne comparée : la clé est ajoutée ou manquante, ou l'une de ses propres valeurs est ajoutée, manquante ou différente (une clé dont seules les sous-clés ont changé reste normale) ; une valeur est en gras quand elle est ajoutée, manquante ou différente. Dans la colonne de référence : une clé est en gras quand elle-même, l'une de ses valeurs ou l'une de ses sous-clés, à toute profondeur, diffère dans au moins un autre fichier ; une valeur, quand elle diffère dans au moins un autre fichier. Les niveaux de chemin au-dessus des clés des fichiers (HKEY_LOCAL_MACHINE, par exemple) ne sont jamais en gras.
NormalIdentique à la référence.

Une colonne montre les clés de son fichier et celles de la référence : une clé que seul un autre fichier possède n'y apparaît pas. La colonne de référence ne montre que ses propres clés. Après chaque comparaison, les branches qui mènent à un changement sont ouvertes et les autres fermées, sauf les parents de la clé choisie, qui sont ouverts ; la clé et la valeur choisies restent sélectionnées dans les colonnes qui les affichent.

Les données sont comparées par ce qu'elles contiennent, pas par la façon dont le fichier les écrit : dword:0000000A et dword:a, hex:0A,0B et hex:0a, 0b, un dword: et le même nombre en hex(4):, un hex(2) REGEDIT4 (octets ANSI) et un de version 5 (octets UTF-16) qui portent le même texte sont tous identiques. Les chaînes se comparent exactement, casse comprise (un saut de ligne de la donnée compte pour un, que le fichier termine ses lignes par \r\n ou par \n). Essayez ci-dessous.

Filtres

CaseEffet (pas sur la colonne de référence)
Show only changes (cochée)L'arbre ne garde que les clés qui ont changé et les branches qui y mènent ; la grille des valeurs cache les valeurs identiques.
Hide empty added nodes (décochée)Cache les clés ajoutées qui n'ont plus de sous-clé dans l'arbre (les valeurs ne comptent pas), niveau après niveau, et les niveaux de chemin restés vides au-dessus d'elles.

Les deux s'appliquent tout de suite, sans nouvelle comparaison. Les arbres sont reconstruits : la clé et la valeur choisies restent sélectionnées partout où elles sont encore affichées, et les branches reviennent à leur ouverture automatique, sauf les parents de la clé choisie, qui sont ouverts.

Quand la comparaison est refaite

  • Compare la construit à partir des fichiers cochés (deux au moins) ; avec moins, il retire les colonnes de fichiers (ou demande d'en cocher deux s'il n'y en a pas). La clé et la valeur choisies sont gardées pour la comparaison suivante.
  • Dès lors (dès qu'une comparaison de deux fichiers ou plus commence), l'affichage suit la liste des fichiers : cocher ou décocher un fichier, choisir une autre référence, ajouter des fichiers (ils arrivent cochés) ou en enlever un relance la comparaison d'elle-même. Décocher jusqu'à ne laisser qu'un fichier retire les colonnes de fichiers ; en recocher un deuxième ramène la comparaison, avec la même clé et la même valeur choisies. Cela dure jusqu'à ce que la liste soit vidée.
  • Avant la première comparaison, rien ne se compare de soi-même (sauf les fichiers donnés au démarrage, voir Prise en main).
  • Choisir comme référence un fichier décoché le coche. Une référence décochée est remplacée par le premier fichier coché à la comparaison suivante ; une référence enlevée, par le premier fichier de la liste.
  • Un changement fait pendant le calcul d'une comparaison est appliqué à la fin de celui-ci : les colonnes correspondent toujours au dernier état de la liste. La colonne d'un fichier enlevé disparaît aussitôt ; les autres restent jusqu'à ce que les nouvelles les remplacent. Les colonnes de recherche restent à leur place.

Pendant le calcul, la liste des fichiers se remplit d'une barre de progression.

5NavigatingNaviguer

  • Synchronized selection. Select a key in any column: every file column selects the same key (opening its parents) if its tree shows it, and clears its selection otherwise; no value stays selected. Select a value in any column, search columns included: the value of the same name is selected in every column that lists it (a search column follows only while it shows that key; a value picked in a search column takes the columns to its key first). A column that follows does not scroll the columns area sideways.
  • Keys. Click the arrow of a key, or double-click the key, to open or close it. With the keyboard: ↑ ↓ move, → opens a key (then goes to its first subkey), ← closes it (then goes to its parent); with the selected key hidden under a closed branch, ← or → first goes to that branch. Right-click a key to select it and open its menu. The trees, like the values grids, create only the rows on screen: a key with thousands of subkeys opens at once.
  • Expand All / Collapse All open or close every branch of every file column. A key hidden under a closed branch stays selected, and shows again selected when its branch opens.
  • Sizes. Drag a column's right edge to resize it (200 px at least), the bar between tree and values to share the height (a new comparison brings the file columns back to their default size). The Name and Type columns of the values grids are shared by all columns: drag their separator, or double-click it to fit the names or types listed in that column's grid.
  • Several values. In a values grid, a click selects or unselects a row (Shift+click selects a range, Ctrl+A every row; ↑ ↓ Home End Page Up Page Down move a single selected row): several rows can be selected for the copy and export commands, which take them in the order they were clicked. Right-click one of the selected rows: a right-click on another row selects it alone. The other columns follow the first selected row. A name or type cut short shows whole on hover; the grid's header follows the rows when a wide datum makes them scroll sideways. Data longer than 2,000 characters (a large binary value) is cut there in the grid, with “…”; copies and searches use all of it.
  • Counters. Under each tree: the keys and values of the file, and the values of the selected key in that file (whatever the filter shows).
  • Dark Theme switches between dark (at start) and light, title bar included; the selection and the scroll positions stay. The theme is not remembered: the next start is dark.
  • Sélection synchronisée. Choisissez une clé dans n'importe quelle colonne : chaque colonne de fichier sélectionne la même clé (en ouvrant ses parents) si son arbre la montre, et vide sa sélection sinon ; aucune valeur ne reste choisie. Choisissez une valeur dans n'importe quelle colonne, colonnes de recherche comprises : la valeur de même nom est sélectionnée dans chaque colonne qui l'affiche (une colonne de recherche ne suit que tant qu'elle montre cette clé ; une valeur choisie dans une colonne de recherche emmène d'abord les colonnes à sa clé). Une colonne qui suit ne fait pas défiler la zone des colonnes sur le côté.
  • Clés. Cliquez sur la flèche d'une clé, ou double-cliquez sur la clé, pour l'ouvrir ou la fermer. Au clavier : ↑ ↓ se déplacent, → ouvre une clé (puis va à sa première sous-clé), ← la ferme (puis va à son parent) ; quand la clé choisie est cachée sous une branche fermée, ← ou → va d'abord à cette branche. Un clic droit sur une clé la sélectionne et ouvre son menu. Les arbres, comme les grilles de valeurs, ne créent que les lignes visibles : une clé de plusieurs milliers de sous-clés s'ouvre tout de suite.
  • Expand All / Collapse All ouvrent ou ferment toutes les branches de toutes les colonnes de fichiers. Une clé cachée sous une branche fermée reste sélectionnée, et réapparaît sélectionnée quand sa branche s'ouvre.
  • Tailles. Faites glisser le bord droit d'une colonne pour la redimensionner (200 px au moins), la barre entre l'arbre et les valeurs pour partager la hauteur (une nouvelle comparaison rend aux colonnes de fichiers leur taille par défaut). Les colonnes Name et Type des grilles de valeurs sont communes à toutes les colonnes : faites glisser leur séparateur, ou double-cliquez dessus pour l'ajuster aux noms ou aux types listés dans la grille de cette colonne.
  • Plusieurs valeurs. Dans une grille de valeurs, un clic sélectionne ou désélectionne une ligne (Maj+clic choisit une plage, Ctrl+A toutes les lignes ; ↑ ↓ Début Fin Page préc. Page suiv. déplacent une seule ligne choisie) : plusieurs lignes peuvent être choisies pour les commandes de copie et d'export, qui les prennent dans l'ordre des clics. Faites un clic droit sur l'une des lignes choisies : un clic droit sur une autre ligne la sélectionne seule. Les autres colonnes suivent la première ligne choisie. Un nom ou un type tronqué s'affiche en entier au survol ; l'en-tête de la grille suit les lignes quand une donnée large les fait défiler sur le côté. Une donnée de plus de 2 000 caractères (une grosse valeur binaire) est coupée là dans la grille, avec « … » ; copies et recherches la prennent en entier.
  • Compteurs. Sous chaque arbre : les clés et valeurs du fichier, et les valeurs de la clé choisie dans ce fichier (quoi que montre le filtre).
  • Dark Theme bascule entre le sombre (au démarrage) et le clair, barre de titre comprise ; la sélection et les défilements restent. Le thème n'est pas retenu : le démarrage suivant est sombre.

6SearchRecherche

Type some text in the search box and press Enter: a Search: … column is added at the right. It lists, file by file, the keys whose path, or the name or data of one of whose values, contains the text (ignoring case). Names and data are searched as the grids show them: a DWORD by its hexadecimal or decimal value (0x0000000a (10)), a multi-string by its text, the default value as (Default). What the grid does not show is not searched (dword:, the bytes of an EXPAND_SZ or MULTI_SZ), but a BINARY value, which the grid shows as written, is found by that text (hex:01,02). The text is taken as typed (no wildcards), without its leading and trailing spaces; the Type column is not searched. A search needs no comparison.

  • The search covers the ticked files (all loaded files if none is ticked), as they are at that moment: the column does not update afterwards.
  • Select a result: the file columns jump to that key, and the column's own grid shows the values that matched (all the values of the key when only its path matched). The first result is selected at once. Each file group shows the file name (its tooltip, the full path), and each result the full key path; (no results) says that nothing matched. The search tree has no right-click menu.
  • The band under the column title counts the results (12 keys in 2 files). The columns area scrolls to a new search column. Several searches can stay open; X closes one. They stay at the right when the comparison is made again, and keep in memory only the files that had results.

Tapez un texte dans la zone de recherche et appuyez sur Entrée : une colonne Search: … s'ajoute à droite. Elle liste, fichier par fichier, les clés dont le chemin, ou le nom ou la donnée de l'une de leurs valeurs, contient le texte (sans tenir compte de la casse). Noms et données sont cherchés tels que les grilles les affichent : un DWORD par sa valeur hexadécimale ou décimale (0x0000000a (10)), une chaîne multiple par son texte, la valeur par défaut sous le nom (Default). Ce que la grille n'affiche pas n'est pas cherché (dword:, les octets d'une valeur EXPAND_SZ ou MULTI_SZ), mais une valeur BINARY, que la grille affiche telle qu'écrite, se trouve par ce texte (hex:01,02). Le texte est pris tel que tapé (pas de jokers), sans ses espaces de début et de fin ; la colonne Type n'est pas cherchée. Une recherche ne demande aucune comparaison.

  • La recherche porte sur les fichiers cochés (tous les fichiers chargés si aucun ne l'est), tels qu'ils sont à cet instant : la colonne ne se met pas à jour ensuite.
  • Choisissez un résultat : les colonnes de fichiers sautent à cette clé, et la grille de la colonne montre les valeurs trouvées (toutes les valeurs de la clé quand seul son chemin correspondait). Le premier résultat est choisi d'emblée. 8Good to knowBon à savoir

  • Names ignore case, data does not. Software and SOFTWARE are the same key; "On" and "ON" are different data. A key or value name is shown with the letter case of the first compared file that has it, the reference first, so a difference of case alone is never shown as a change. A path level that is not a key of its own (SOFTWARE in most exports) takes the case of the first key below it, which can differ from one column to another; a search column shows each file's own spelling.
  • Names as in Registry Editor. The default value (@) reads (Default), and names are shown without their .reg escapes (C:\\Windows reads C:\Windows). A value literally named "(Default)" is a different value from the default one.
  • Data is compared by what it holds. The same number written two ways (dword:0000000a and hex(4):0a,00,00,00), hex bytes in another case or spacing, the same text in a REGEDIT4 export (ANSI) and a version 5 one (UTF-16): identical (see Reading a comparison). Strings compare exactly as written (line breaks aside, see below). Long values split over several lines (\ at the end) are joined first, so the line length does not matter.
  • Strings on several lines. Registry Editor writes the line breaks of a string as they are: the value continues on the following lines up to its closing quote, and is kept exactly as written (reg export writes a line break of the data as \r\n). The grid shows it on several lines, one break per break of the data, and compares it so: the same string from a file whose lines end with \n (normalized by git) is identical. A string broken by a backslash before its closing quote ("C:\Dir\", hand-written) is dropped with its line, as Registry Editor drops it; the lines below are read as usual.
  • Read like Registry Editor reads it. A comment after the data ("x"=dword:1 ; note) or after a key ([HKEY_…\Key] ; note) is not part of it; comment and blank lines inside a long hex value are skipped; [HKEY_…\Key\] is [HKEY_…\Key]; a key line starting with a space ([ HKEY_…]) is ignored with the values under it; only lines starting with " or @ are values. A line that cannot be read is skipped: no file is ever refused.
  • Deletion entries ([-HKEY_…], "Value"=-) are compared as written, like any other key or value: a [-HKEY_…] key shows under its own root, -HKEY_…, and a deleted value as type SZ with data -.
  • Files are read once, when they are loaded. To see a file changed on disk, remove it and load it again.
  • Encodings. Version 5 files (UTF-16 with a BOM, or little-endian UTF-16 without one) and UTF-8 files are read as they are; a file that is not valid UTF-8 is read in the ANSI code page. A REGEDIT4 file without a byte order mark is ANSI: it is read in the code page of your system (Windows-1252 on a Western European system), and so are its EXPAND_SZ and MULTI_SZ data. A REGEDIT4 export and a version 5 export of the same key compare by their text: their EXPAND_SZ and MULTI_SZ values are identical when they hold the same text.
  • Folders dropped on the window or the exe, or given on the command line, are searched for .reg files, 32 levels deep at most, each file once; hidden and system files and folders, junctions and folder links (one pointing back to a parent would loop), and the subfolders that cannot be read, are skipped, and a folder that cannot be read at all is reported. A file without extension given directly is taken when its text starts with a .reg header (Windows Registry Editor… or REGEDIT4). A file with another extension (.txt) is ignored. A path that does not exist is reported in the status bar (Could not read: … (not found)), and the others are still loaded. Files are listed and read in the background: the window stays responsive, and the status bar says Loading….
  • Any file can be opened with Browse .reg Files (its All files filter). A file without any key is loaded all the same, and the status bar says so.
  • Large files. The trees and the values grids create only the rows on screen: two exports of 10,000 keys compare in about a second, and a key with thousands of subkeys or values opens at once. A whole file is read into memory. The interface is in English.
  • Les noms ignorent la casse, les données non. Software et SOFTWARE sont la même clé ; "On" et "ON" sont des données différentes. Un nom de clé ou de valeur s'affiche avec la casse du premier fichier comparé qui le contient, la référence d'abord : une simple différence de casse n'est donc jamais signalée comme un changement. Un niveau de chemin qui n'est pas une clé à part entière (SOFTWARE dans la plupart des exports) prend la casse de la première clé en dessous, qui peut varier d'une colonne à l'autre ; une colonne de recherche montre l'orthographe de chaque fichier.
  • Les noms comme dans l'Éditeur du Registre. La valeur par défaut (@) s'affiche (Default), et les noms s'affichent sans leurs échappements .reg (C:\\Windows se lit C:\Windows). Une valeur nommée littéralement "(Default)" est une autre valeur que la valeur par défaut.
  • Les données sont comparées par ce qu'elles contiennent. Un même nombre écrit de deux façons (dword:0000000a et hex(4):0a,00,00,00), des octets hexadécimaux dans une autre casse ou un autre espacement, le même texte dans un export REGEDIT4 (ANSI) et un export version 5 (UTF-16) : identiques (voir Lire une comparaison). Les chaînes se comparent exactement telles qu'écrites (sauts de ligne à part, voir ci-dessous). Les longues valeurs coupées sur plusieurs lignes (\ en fin de ligne) sont d'abord recollées : la longueur des lignes ne compte donc pas.
  • Chaînes sur plusieurs lignes. L'Éditeur du Registre écrit les sauts de ligne d'une chaîne tels quels : la valeur continue sur les lignes suivantes jusqu'à son guillemet fermant, et est gardée exactement telle qu'écrite (reg export écrit un saut de ligne de la donnée en \r\n).   • Lu comme le lit l'Éditeur du Registre. Un commentaire après la donnée ("x"=dword:1 ; note) ou après une clé ([HKEY_…\Clé] ; note) n'en fait pas partie ; les lignes de commentaire ou vides au milieu d'une longue valeur hexadécimale sont sautées ; [HKEY_…\Clé\] vaut [HKEY_…\Clé] ; une ligne de clé qui commence par une espace ([ HKEY_…]) est ignorée avec les valeurs qui la suivent ; seules les lignes qui commencent par " ou @ sont des valeurs.   • Encodages. Les fichiers version 5 (UTF-16 avec BOM, ou UTF-16 little-endian sans BOM) et UTF-8 sont lus tels quels ; un fichier qui n'est pas de l'UTF-8 valide est lu dans la page de codes ANSI. Un export REGEDIT4 et un export version 5 de la même clé se comparent par leur texte : leurs valeurs EXPAND_SZ et MULTI_SZ sont identiques quand elles portent le même texte.

10Reading .reg filesLecture des fichiers .reg

Services/RegFileParser.cs reads the whole file into memory and turns it into a RegFile: path, name, last write time, size, IsRegedit4, LfLines (more lines end with \n alone than with \r\n; the breaks inside strings are data, not counted), and Data, a dictionary key path → value name → raw value text. Both levels ignore case (OrdinalIgnoreCase).

Encoding

  1. A byte order mark decides: FF FE UTF-16 LE, FE FF UTF-16 BE, EF BB BF UTF-8.
  2. No mark, but a zero byte in the first 512 bytes: UTF-16 LE.
  3. A file starting with REGEDIT4: the system's ANSI code page (GetACP, through CodePagesEncodingProvider).
  4. Otherwise strict UTF-8; if the bytes are not valid UTF-8, the ANSI code page.

Lines

  • The text is cut into lines at \r\n, \n or \r; each line is read without its leading and trailing blanks. Empty lines and lines starting with ; are skipped.
  • The first line that is not empty is the header: REGEDIT4 sets IsRegedit4. Lines before the first key are not values.
  • […] opens a key: its path is the text up to the ] that ends the line or that a ; comment follows (a name may hold ] itself: [HKEY_CURRENT_USER\Software\[x]]; with no such ], up to the last one), without trailing backslashes. A key line with no ], or whose name starts with a blank or with - and a blank ([ HKEY…], [- HKEY…]), names no key: the values under it are dropped, as Registry Editor drops them. A key that appears twice is one key.
  • Only a line starting with " or @ is a value (#"x"=… or foo=bar are skipped): a quoted name, whose closing quote is found by honoring \" and \\ (kept as written, escapes included), or @, the default value, stored under the empty name; then =, blanks allowed around it.
  • A string (" after =) goes up to its closing quote, on that line or the lines below when its data holds line breaks: the characters between the quotes are kept exactly as the file has them, line breaks included. What follows the closing quote (a comment) is not data. A quote on a later line closes the string only when it ends that line (a comment may follow): otherwise the string is broken (an unescaped \ before its quote made the next value's quote close it) and only its line is dropped; so is a string never closed.
  • Other data ends at a ; (a comment). Ending with \, it goes on with the next lines of hex data, each read without its blanks and its comment and appended without the \, until one that does not end with one; blank and comment lines between them are skipped, and a line that is not hex data (digits, commas, blanks) ends the value and is read again as a line of its own.
  • A value that appears twice in a key keeps its last data. No file is refused: a line that cannot be read is skipped.

Services/RegFileParser.cs lit tout le fichier en mémoire et en fait un RegFile : chemin, nom, date de dernière modification, taille, IsRegedit4, LfLines (plus de lignes finissent par \n seul que par \r\n ; les sauts dans les chaînes sont des données, non comptés), et Data, un dictionnaire chemin de clé → nom de valeur → texte brut de la valeur. Les deux niveaux ignorent la casse (OrdinalIgnoreCase).

Encodage

  1. Une marque d'ordre des octets décide : FF FE UTF-16 LE, FE FF UTF-16 BE, EF BB BF UTF-8.
  2. Pas de marque, mais un octet nul dans les 512 premiers octets : UTF-16 LE.
  3. Un fichier qui commence par REGEDIT4 : la page de codes ANSI du système (GetACP, par CodePagesEncodingProvider).
  4. Sinon UTF-8 strict ; si les octets ne sont pas de l'UTF-8 valide, la page de codes ANSI.

Lignes

  • Le texte est découpé en lignes à chaque \r\n, \n ou \r ; chaque ligne est lue sans ses blancs de début et de fin. Les lignes vides et celles qui commencent par ; sont ignorées.
  • La première ligne non vide est l'en-tête : REGEDIT4 fixe IsRegedit4. Les lignes avant la première clé ne sont pas des valeurs.
  • […] ouvre une clé : son chemin est le texte jusqu'au ] qui termine la ligne ou que suit un commentaire ; (un nom peut contenir ] lui-même : [HKEY_CURRENT_USER\Software\[x]] ; sans un tel ], jusqu'au dernier), sans barres obliques inverses finales. Une ligne de clé sans ], ou dont le nom commence par un blanc ou par - et un blanc ([ HKEY…], [- HKEY…]), ne nomme aucune clé : les valeurs qui la suivent sont écartées, comme l'Éditeur du Registre les écarte. Une clé qui apparaît deux fois est une seule clé.
  • Seule une ligne qui commence par " ou @ est une valeur (#"x"=… ou foo=bar sont ignorées) : un nom entre guillemets, dont le guillemet fermant est trouvé en respectant \" et \\ (gardé tel qu'écrit, échappements compris), ou @, la valeur par défaut, rangée sous le nom vide ; puis =, des blancs permis autour.
  • Une chaîne (" après =) va jusqu'à son guillemet fermant, sur cette ligne ou les suivantes quand sa donnée contient des sauts de ligne : les caractères entre les guillemets sont gardés exactement tels que le fichier les a, sauts de ligne compris. Ce qui suit le guillemet fermant (un commentaire) n'est pas une donnée. Un guillemet sur une ligne suivante ne ferme la chaîne que s'il termine cette ligne (un commentaire peut suivre) : sinon la chaîne est cassée (un \ non échappé avant son guillemet a fait fermer la chaîne par le guillemet de la valeur suivante) et seule sa ligne est écartée ; de même pour une chaîne jamais fermée.
  • Les autres données s'arrêtent à un ; (un commentaire). Terminées par \, elles continuent avec les lignes de données hexadécimales suivantes, chacune lue sans ses blancs ni son commentaire et ajoutée sans le \, jusqu'à une ligne qui ne se termine pas par \ ; les lignes vides ou de commentaire entre elles sont sautées, et une ligne qui n'est pas une donnée hexadécimale (chiffres, virgules, blancs) termine la valeur et est relue comme une ligne à part.
  • Une valeur qui apparaît deux fois dans une clé garde sa dernière donnée. Aucun fichier n'est refusé : une ligne illisible est sautée.

11The comparison engineLe moteur de comparaison

Services/DiffEngine.cs is built once per comparison, from the ticked files with the reference at index 0, and is not modified afterwards.

  • AllKeys: key path → the files that have it. AllValues: key path → value name → the files that have it. Both keep the spelling of the first file that has the name, the reference first. SortedKeys: every key path in tree order (KeyPathComparer: level by level, each level's names without regard to case, so A\X comes before AB).
  • Key status in a file: the reference gives Reference (or Hidden if it lacks the key); another file Added (only it), Missing (only the reference), Exists (both) or Hidden (neither).
  • Value status: Added, Missing or Hidden on the same rule; when both have it, Identical if they hold the same data (RegData.Same, below), else Different.
  • Same data (Services/RegData.cs): equal raw texts are; otherwise both are put in one spelling and compared. Strings stay as written, except their line breaks (as the grid shows them): in a file whose lines end with \r\n, each \r\n is one \n of the data (reg.exe writes a \n of the data as \r\n, a \r\n as \r\r\n); a file whose lines end with \n alone (converted by git or an editor, RegFile.LfLines: the ending more lines use) holds the data as it is. dword:, qword:, hex(4): (4 bytes) and hex(b): (8 bytes) become their number (the type in any spelling: hex(04); a trailing comma allowed); a hex(2) or hex(7) list becomes its text as UTF-16 code units: the bytes themselves in a version 5 file, the ANSI bytes of a REGEDIT4 one converted (so unpaired surrogates stay distinct); any other hex list becomes its type and its bytes (hex: is type 3), case and spacing aside. A value that cannot be read so keeps its raw text.
  • A key changed in a file when it is Added or Missing there, or when one of the value names any compared file has under it is Added, Missing or Different there.
  • For each file, the set of changed keys and all their ancestors is computed once (KeyOrSubtreeChanged, then a constant-time lookup), and their union over the other files for the reference (ChangedAnywhereForKey). ValueChangedAnywhere tells, for the reference, whether a value differs in at least one other file.

Cost: one pass over every key and value of every file to build the indexes, then, per non-reference file, one status per key, and at most one per value name of the union.

Services/DiffEngine.cs est construit une fois par comparaison, à partir des fichiers cochés avec la référence à l'index 0, et n'est plus modifié ensuite.

  • AllKeys : chemin de clé → les fichiers qui l'ont. AllValues : chemin de clé → nom de valeur → les fichiers qui l'ont. Les deux gardent l'orthographe du premier fichier qui a le nom, la référence d'abord. SortedKeys : tous les chemins de clés dans l'ordre de l'arbre (KeyPathComparer : niveau par niveau, les noms de chaque niveau sans tenir compte de la casse, donc A\X avant AB).
  • État d'une clé dans un fichier : la référence donne Reference (ou Hidden si elle n'a pas la clé) ; un autre fichier Added (lui seul), Missing (la référence seule), Exists (les deux) ou Hidden (aucun).
  • État d'une valeur : Added, Missing ou Hidden selon la même règle ; quand les deux l'ont, Identical s'ils portent la même donnée (RegData.Same, ci-dessous), sinon Different.
  • Même donnée (Services/RegData.cs) : deux textes bruts égaux le sont ; sinon les deux sont mis dans une même écriture et comparés. Les chaînes restent telles qu'écrites, sauf leurs sauts de ligne (comme la grille les affiche) : dans un fichier dont les lignes finissent par \r\n, chaque \r\n est un \n de la donnée (reg.exe écrit un \n de la donnée en \r\n, un \r\n en \r\r\n) ; un fichier dont les lignes finissent par \n seul (converti par git ou un éditeur, RegFile.LfLines : la fin de ligne qu'utilisent le plus de lignes) contient la donnée telle quelle. dword:, qword:, hex(4): (4 octets) et hex(b): (8 octets) deviennent leur nombre (le type écrit de n'importe quelle façon : hex(04) ; une virgule finale permise) ; une liste hex(2) ou hex(7) devient son texte en unités UTF-16 : les octets eux-mêmes dans un fichier version 5, les octets ANSI d'un fichier REGEDIT4 convertis (les demi-paires isolées restent donc distinctes) ; toute autre liste hex devient son type et ses octets (hex: est le type 3), casse et espacement à part. Une valeur illisible ainsi garde son texte brut.
  • Une clé a changé dans un fichier quand elle y est Added ou Missing, ou quand l'un des noms de valeurs qu'un fichier comparé a sous elle y est Added, Missing ou Different.
  • Pour chaque fichier, l'ensemble des clés changées et de tous leurs ancêtres est calculé une fois (KeyOrSubtreeChanged, ensuite consulté en temps constant), ainsi que leur union sur les autres fichiers pour la référence (ChangedAnywhereForKey). ValueChangedAnywhere dit, pour la référence, si une valeur diffère dans au moins un autre fichier.

Coût : un passage sur chaque clé et valeur de chaque fichier pour construire les index, puis, par fichier autre que la référence, un état par clé, et au plus un par nom de valeur de l'union.

12Building the columnsConstruction des colonnes

Tree (FileColumnViewModel.BuildTree)

  1. For each key of SortedKeys: skipped if its status here is Hidden, or if Show only changes is on, the column is not the reference, and neither the key nor anything under it changed.
  2. The path is split on \; a node is created for each segment not yet in the tree (a dictionary indexes the nodes by path).
  3. The node of the key itself gets its status. Added or Missing → bold. If one of its values is Added, Missing or Different → bold, and blue when the key itself exists on both sides. In the reference column, bold when ChangedAnywhereForKey. The nodes of path levels that are not keys get no status.
  4. Hide empty added nodes (not on the reference): depth first, an Added node, or a path level, without children is removed, from the tree and from the index (so a key chosen elsewhere is not selected here either); its parent is examined after it, hence the cascade.
  5. Each node is expanded when one of its descendants is a change, collapsed otherwise.
  6. The tree is shown as a flat list (ViewModels/TreeRows.cs): the rows of the nodes whose parents are all open, in depth-first order, in a ListBox on a VirtualizingStackPanel, each row indented by its depth. Opening or closing a node inserts or removes the rows below it in one change; Expand All, Collapse All and a rebuild list the rows again once. Only the rows on screen get a control, where a TreeView creates one per open node. The list is kept as wide as its widest row (TreeRows.Widest: indentation, arrow and the text's estimated width, kept up to date as rows come and go), not the widest on screen, so its horizontal scrolling stays put while it scrolls up and down.

Values grid

  • The rows are the value names that any compared file has under the selected key, sorted with OrdinalIgnoreCase (the default value first). If this file lacks the key, the grid stays empty (the struck-through node already says so).
  • Other columns, Show only changes on: Added, Missing and Different only. Off: everything but Hidden. Reference: the values it has.
  • Type and data come from this file's raw value, empty for a Missing value. Bold: changed here; in the reference, changed in some other file (ValueChangedAnywhere).
  • The grid is a ListBox on a VirtualizingStackPanel: only the rows on screen are created. Data longer than 2,000 characters is drawn cut there (ShownValue). Search (SearchColumnViewModel)

Built once from the term and the list of files it covers. For each file and each key: the key matches if its path contains the term; a value matches if its name as shown, or the text GetDisplayValue gives for it, contains the term (OrdinalIgnoreCase). Results are grouped per file, keys in tree order; the column keeps only the files that have results, and its band counts them. Selecting a key sets the shared selection, so the file columns follow; its grid lists the matched values, or every value when only the key matched, and takes part in the value selection like a file column's.

Export (RegFileWriter)

  • Header Windows Registry Editor Version 5.00, or REGEDIT4 for a REGEDIT4 file, and an empty line; then one […] header for each parent of the exported key, from the hive down, without values (none for a deletion entry).
  • Key and value names take the file's own spelling: the columns show the spelling of the first file that has a name.
  • Tree export: the key and every key of the file whose path starts with key\, in tree order, each with all its values sorted by name, then an empty line. Values export: the key and the selected values found in the file, in the order they were selected (each name's spelling found in one lookup).
  • Values are written "name"=raw (@=raw for the default value), the raw text exactly as read, except a string of a file whose lines end with \n (LfLines), whose \n become \r\n, as reg.exe writes the breaks of the data. Lines end with CR LF. The file is written in UTF-16 LE with a BOM, as Registry Editor does, or for a REGEDIT4 file in the ANSI code page without any mark, a character it cannot write being refused (EncoderFallback.ExceptionFallback). A tree export of a path level that is not a key writes no header for it, nor for the levels down to the first keys below it.
  • The proposed name is the last segment of the key, with characters that are not allowed in file names replaced by _. A write that fails (no write access, a full disk) is told in the status bar.

Loading (DragDropService, MainWindowViewModel)

  • Everything here runs off the UI thread: the drop returns at once, the paths are resolved and each file parsed in Task.Run, and each file joins the list on the UI thread when it is read (IsLoading; loads queue up, a drop made during one waits for it). A dropped or passed folder: its first entry is read (a folder that cannot be listed is reported), then each level is listed (IgnoreInaccessible; hidden and system entries skipped), 32 levels deep at most; a subfolder that is a junction or a link (LinkTarget) is not followed, and each file is taken once. A file ending in .reg: taken. A file with another extension: ignored. A file without extension: taken if its first 4 KB, decoded as the parser would, start with a .reg header. A path that does not exist is reported ((not found)), as is one that cannot be read, in the status bar, and the others are still loaded.
  • Each path is made absolute; a file already loaded (same path, ignoring case) is not loaded again. A file without any key is loaded. Each of these cases, and a file that cannot be read, is told in the status bar, and the comparison that follows keeps those messages beside its count; a file that fails to load is also written to the console output (which only shows when the output is redirected).
  • Display names: the file name when every loaded file is in the same folder, the full path otherwise. The Reference list, the column titles and the search columns' file groups show the file name; files sharing one get as much of their folder as tells them apart (a.reg (x), a.reg (C:\x) and a.reg (D:\x), a.reg (C:\) at a drive root, Services/FileNames.cs), and the full path as a tooltip.

Title bar

Construite une fois à partir du terme et de la liste des fichiers couverts. Export (RegFileWriter)

  • En-tête Windows Registry Editor Version 5.00, ou REGEDIT4 pour un fichier REGEDIT4, et une ligne vide ; puis un en-tête […] pour chaque parent de la clé exportée, depuis la ruche, sans valeurs (aucun pour une entrée de suppression).
  • Les noms de clés et de valeurs prennent l'orthographe du fichier lui-même : les colonnes montrent celle du premier fichier qui a le nom.
  • Export d'arbre : la clé et chaque clé du fichier dont le chemin commence par clé\, dans l'ordre de l'arbre, chacune avec toutes ses valeurs triées par nom, puis une ligne vide. Export de valeurs : la clé et les valeurs choisies trouvées dans le fichier, dans l'ordre où elles ont été choisies (l'orthographe de chaque nom trouvée en une recherche).
  • Les valeurs s'écrivent "nom"=brut (@=brut pour la valeur par défaut), le texte brut exactement tel que lu, sauf une chaîne d'un fichier dont les lignes finissent par \n (LfLines), dont les \n deviennent \r\n, comme reg.exe écrit les sauts de la donnée. Les lignes finissent par CR LF. Le fichier est écrit en UTF-16 LE avec BOM, comme le fait l'Éditeur du Registre, ou pour un fichier REGEDIT4 dans la page de codes ANSI sans aucune marque, un caractère qu'elle ne sait pas écrire étant refusé (EncoderFallback.ExceptionFallback). L'export d'arbre d'un niveau de chemin qui n'est pas une clé n'écrit d'en-tête ni pour lui, ni pour les niveaux qui le séparent des premières clés en dessous.
  • Le nom proposé est le dernier segment de la clé, les caractères interdits dans un nom de fichier remplacés par _. Une écriture qui échoue (pas le droit d'écrire, disque plein) est signalée dans la barre d'état.

Chargement (DragDropService, MainWindowViewModel)

  • Tout ici s'exécute hors du thread de l'interface : le dépôt rend la main aussitôt, les chemins sont résolus et chaque fichier analysé dans Task.Run, et chaque fichier rejoint la liste sur le thread de l'interface une fois lu (IsLoading ; les chargements font la queue, un dépôt fait pendant l'un attend sa fin). Un dossier déposé ou passé : sa première entrée est lue (un dossier impossible à lister est signalé), puis chaque niveau est listé (IgnoreInaccessible ; entrées cachées et système ignorées), sur 32 niveaux au plus ; un sous-dossier qui est une jonction ou un lien (LinkTarget) n'est pas suivi, et chaque fichier n'est pris qu'une fois. Un fichier en .reg : pris. Un fichier d'une autre extension : ignoré. Un fichier sans extension : pris si ses 4 premiers Ko, décodés comme le ferait l'analyseur, commencent par un en-tête .reg. Un chemin qui n'existe pas est signalé ((not found)), comme un chemin illisible, dans la barre d'état, et les autres sont tout de même chargés.
  • Chaque chemin est rendu absolu ; un fichier déjà chargé (même chemin, sans tenir compte de la casse) n'est pas rechargé. Un fichier sans aucune clé est chargé. Chacun de ces cas, et un fichier illisible, est signalé dans la barre d'état, et la comparaison qui suit garde ces messages à côté de son décompte ; un fichier dont le chargement échoue est aussi écrit dans la sortie console (visible seulement quand la sortie est redirigée).
  • Noms affichés : le nom du fichier quand tous les fichiers chargés sont dans le même dossier, le chemin complet sinon. La liste Reference, les titres de colonnes et les groupes de fichiers des colonnes de recherche montrent le nom du fichier ; des fichiers de même nom reçoivent autant de leur dossier qu'il en faut pour les distinguer (a.reg (x), a.reg (C:\x) et a.reg (D:\x), a.reg (C:\) à la racine d'un disque, Services/FileNames.cs), et le chemin complet en info-bulle.

Barre de titre

À l'ouverture de la fenêtre et à chaque changement de thème : DwmSetWindowAttribute avec DWMWA_USE_IMMERSIVE_DARK_MODE (attribut 20, et 19 pour les versions de Windows 10 antérieures à 20H1 ; celui que Windows ne connaît pas est ignoré), puis SetWindowPos(SWP_FRAMECHANGED), une paire WM_NCACTIVATE désactivé/activé (le second seulement quand la fenêtre est au premier plan, pour qu'une fenêtre ouverte derrière une autre reste dessinée inactive) et RedrawWindow(RDW_FRAME), pour que le cadre soit redessiné tout de suite et non à la prochaine activation.
